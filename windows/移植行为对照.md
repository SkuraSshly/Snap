# Windows 移植的行为标准

preview.17 的钉图缩放与动效调整、实际专项和全流程回归见《完整流程测试.md》。以下为历史资料。

preview.16 已恢复实际运行验收，修复启用开关、引擎配置和翻译清空问题；结果与范围见《完整流程测试.md》。以下保留历史资料，仅编译等安排属于旧版。

当前 preview.14 的翻译状态模型、OCR 几何排版与长截图引擎重写见 `Mac交互对齐.md`；本轮仅编译打包，未运行测试。以下保留历史记录。

以 `Sources/Velos` 的控制流程、状态变化和边界条件为依据，C# 使用对应的 Windows 接口完成相同操作。验收不再仅检查“有这个按钮、窗口能打开”。源文件保留在 Mac 目录，Windows 改动仅位于 `windows/`。

## 长图与翻译窗口（preview.12）

历史 preview.13 的长图状态、共用菜单／分段控件、录屏／GIF 流程见 `Mac交互对齐.md`。托盘按用户新要求改为左键直接显示界面、右键菜单；下方“左右键菜单”均属历史行为。

翻译窗口对照 Mac `TranslationView.swift` 及结果窗口参考图，修复拖动命中与圆角布局，保留文字编辑／选择及钉住操作。长图不改变采集物理尺寸，显示使用独立像素块，移除整图特效，提供 100% 查看和当前 DPI 换算。完整说明与尚待实机验证项见 `长图与翻译改进.md`；本轮未运行测试。

## Mac 2.3 增量（preview.11）

新版参考为 `6ac2241b854af84d1c6c835f188278f6b98b4696`。录屏系统事件由 WTS／电源消息承担，暂停说明、睡眠停止保存、启动时序和长图期间停止录屏已接入。翻译的配置与机密分离，不回填已保存 Key，存在性查询和实际读取分开；OCR 使用当前用户管道与 Job Object，按需启动并在空闲 30 秒后退出。几何光标更新为 2.3 的细长等腰三角。

详细文件映射和差异见 `2.3开发对照.md`。设置子进程按新版“先量再决定”保留为待测量项。本轮只构建打包，由用户验收，未新增运行或内存结论。

## 设置细节调整（preview.10）

根据用户最新指定，窗口操作采用 Windows 的右上角排列：最小化、最大化／还原、关闭，替代旧稿左上角交通灯。保留暖色圆角卡片与统一矢量图标；最大化状态对应重叠窗口的还原图标。截图／录屏的路径改为单行星号列布局，共用剩余宽度和完整路径提示。本轮不运行测试，交用户验收。

## 控制点悬停状态（preview.9）

`AnnotationController.mouseUp` 在 Mac 中清除 `resizing`；Windows `MarkCanvas.EndMark` 和 `OnLostMouseCapture` 现在同样清除。按住拖动期间使用当前控制点，松开后重新按指针命中查询。修复点击后残留方向的问题，兼顾截图与编辑器、拖动中断回滚。专项先复现旧错误，再验证修复；双架构实际鼠标确认无需再次点击。

## 逐项交互复核（preview.8）

`SelectionGroup.cs` 统一截图、录屏、翻译的跨屏全屏目标与恢复区域；`CaptureSurface.SelectionCommitted` 将翻译“松开完成区域”与其他状态变化分开。录屏的右键退级、托盘菜单收起等待和系统关窗结束会话均补齐。`ShotWindows.cs` 对齐编辑器 ×1.25／×0.8 快捷缩放、Ctrl+W；`RecordingThumbnail.cs` 修复进度值改变后实际寻址和暂停停止轮询。

Windows 普通文件拖拽使用 CF_HDROP，未保存截图由接收方取数据时生成临时 PNG；虚拟文件协议继续提供。它是 Windows 接收程序兼容路径，不能用单个合成接收器的成功宣称所有聊天程序都通过。具体测试层级与功能索引见 `逐项功能检查.md`。

## Mac 2.2 对齐（preview.7）

新基线来自官方 `v2.2`：`25dbf2def57508e5c60c914229f9a660d739a7b2`，只读副本位于忽略的 `windows/bin/dev/mac-v2.2/`。原工作区 Mac 代码仍保留原 HEAD。

- `UI/WarmCursors.swift` → `UI/WarmCursors.cs`、`Windows/Capture/NativeCursor.cs`：26 DIP 矢量、强弱三角、白边投影、四向中心、实际 DPI 栅格、句柄缓存与释放；选区、标注及滑块共用。
- `Capture/SelectionOverlay` 圆角与结果裁切 → `CornerRadiusControl.cs`、`CaptureSurface.cs`、`Core/Screenshot/RoundedCorners.cs`、`ShotImage.cs`：逻辑半径到物理像素、PNG 透明、JPEG 白底和编辑器随形投影。Windows HEIC 不保证 alpha，透明图片回退 PNG。
- `LongCapture/ScrollStitcher.swift` → `Core/LongCapture/ScrollStitcher*.cs`：2.2 的起点、容差、动态顶栏／侧栏、重叠保护、15 帧／3 精确对恢复、回滚预览；对应合成基线在 `ScrollStitcher22Tests.cs`。内部兼容的横向图片处理不再作为长截图 UI 入口。
- `LongCaptureAutoScroll.swift` → `Core/LongCapture/AutoScroll.cs`、`Windows/Capture/WheelInput.cs`、`LongCaptureSession.cs`：60 拍状态机、进出选区、150–450 DIP/s 估计速度、方向纠正、到底／长度上限停止。Windows 发送高精度滚轮单位而非 CGEvent 像素手势，实际步长由目标应用决定；UIPI 不可绕过。手动模式没有鼠标钩子或定时输入。
- `LongCapturePreview` → `ScrollStitcher.Preview.cs`：按面板物理像素双线性生成，跟随当前位置、30 fps 加末帧 40 ms。Core Graphics 高质量缩小和 Windows 采样器存在滤波差异，最终长图仍使用未缩放原始帧。
- 设置／启动：800×600 下限、侧栏选中块有限时弹性移动、键帽和修饰键显示、录制时暂停全局绑定、欢迎状态持久化、托盘左右键菜单。系统字体、原生菜单、窗口边框与毛玻璃仍有平台差异。
- `Overlay/HintBar.swift` → `UI/ModeHint.cs`：13 DIP 分层文字、实际快捷键、区域／全屏模式与上下避让；截图、录屏、翻译共用。全屏跨屏目标和原选区保存由共享选区调度器维护；合成双屏夹具覆盖这些状态，不能替代真实混合 DPI 多屏验收。

## 截图标注行为（preview.6）

- `AnnotationController.swift` → `Screenshot/MarkCanvas.cs`：工具与标注选择分离、稳定标注身份、撤销选择、一秒样式合并、误触阈值、文字输入状态和实时样式。
- `AnnotationGeometry.swift` → `Screenshot/Markup.cs` 与 `MarkCanvas.cs`：外框包含线宽、真实路径命中、箭头头部命中、最近可见控制点、移动边界和 Shift 裁切。
- `AnnotationRenderer.swift` → `Markup.cs`、`PixelEffects.cs`：荧光笔、字色、文字底色边距、马赛克／模糊实时预览和模糊 sigma。CPU 三次方框近似高斯与 Mac Core Image 的像素结果仍可能不同。
- `ColorPicker.swift` → `Core/Screenshot/AnnotationColorCode.cs` 与 `Screenshot/AnnotationColorPicker.cs`：实时 HSV、颜色代码、RGBA／尾部 alpha、剪贴板颜色、关闭保留修改。
- `AnnotationEditorWindow.swift` → `Screenshot/ShotWindows.cs`：默认矩形，复用同一标注交互；输入法和调色盘自身的按键不会被截图快捷操作提前消费。

对应夹具位于 `Debug/AnnotationParityReview.cs` 与 `tests/Velos.Tests/AnnotationColorCodeTests.cs`，包括四档比例的误触、命中、撤销、文字样式、真实像素预览和颜色代码检查。

## 视觉对应（preview.4）

`UI/WarmStyle.swift` 与 `Annotation/AnnotationToolbar.swift` 对应 Windows 的 `UI/ActionIcon.cs`、`Screenshot/CaptureChrome.xaml`、`MarkupToolbar.cs`；统一圆头矢量、32 DIP 按钮、42 DIP 胶囊、18 DIP 色点及选中外环、图标实心开关。设置参考对应 `SettingsWindow.xaml`、`SettingsWindow.xaml.cs` 与 `Screenshot/SettingsPane.cs`，采用圆形窗口控制、16 DIP 窗口圆角、14 DIP 卡片圆角与柔和阴影。实际截图与多缩放图标图册用于检查渲染，不以参数相同代替视觉验收。Mac 字体、SF Symbols、NSVisualEffect 的像素输出不宣称完全相同。

## 已按源码修正的行为（preview.3）

- `Capture/CaptureCoordinator.swift` → `Core/Screenshot/CaptureSessionRules.cs`、`App.xaml.cs`：选区只响应本功能的重复快捷键；其他功能不取消或替换它。录制期间没有选区时仍可截图与翻译，长截图期间忽略其他捕获快捷键。
- `Capture/FrontmostAppGuard.swift` → `Windows/Capture/SelectionFocus.cs` 与三个控制器：选区期间监听前台变化；切到其他程序就取消遮罩，正常结束时有条件地归还焦点；停止监听后旧事件不能取消新会话。
- `Pin/PinManager.swift` → `Core/Screenshot/PinLayout.cs`、`Screenshot/PinWindow.cs`：小图原位；大图缩至可见区 60% 并居中；长宽比严格大于 2.5 才按长图处理，长图交叉方向最多占 45%，滚动方向视口最多占 85%。
- `Pin/PinWindow.swift` → 同上：鼠标锚点缩放、10%～800% 范围、20 点最小尺寸、长图缩放时保留滚动位置、透明度步长与范围、复制与比例反馈、透明度菜单。描边叠加绘制，不挤占图片像素；滚动条使用叠加布局。
- `PinView.copyToClipboard/saveImage` → `ScreenshotController.cs`：钉图复制原生图片，不使用普通输出的 1x 选项；“存储为…”打开路径选择并按当前格式保存原生图，不等同于缩略图保存到默认目录。
- `Thumbnail/ThumbnailManager.swift` → `ScreenshotLayout.ThumbnailSize`、`ThumbnailShelf.cs`：统一缩略图尺寸；新缩略图从右侧滑入，旧图上移；按生命周期消失，取消固定四张上限，不因连续截图关闭仍在使用的缩略图；开始淡出时就重排。
- `Thumbnail/ThumbnailView.swift` → 两种缩略图：截图的“保存”完成后切换为“显示文件”；录屏删除在右上、GIF / 拷贝 / 显示文件在右下，窄图悬停时避免与时长徽标重叠；成功拖出文件后关闭。
- `Capture/ScreenFreezer.swift`、`UI/WindowIdentifiers.swift` → `Windows/Capture/Desktop.cs` 与缩略图：临时窗口统一从截图与窗口识别排除；设置、编辑、预览、钉图作为普通可捕获内容；录制时恢复共享临时界面的可见性，录制控制条和红框继续排除。
- `Annotation/AnnotationEditorWindow.swift` → `Screenshot/ShotWindows.cs`：依照实际图像和视口选择完整显示、按宽度或按高度滚动，普通长图也适用；工具栏预留固定空间，比例显示改为 1.2 秒后淡出，手动缩小的下限为能看到整张图。
- `ScreenTranslate/Translation/TranslationModel.swapLanguages` → `TranslationWindow.cs`：只交换原文和目标语言，不用旧译文替换原文。
- `ScreenTranslate/UI/TranslationWindow.swift` → 同上：钉住只改变可调整状态，内容继续随文字高度变化；真正开始拖边缘才切到自由尺寸。取消钉住恢复默认宽度和自动高度。快捷键修饰键按源码严格匹配。
- `LongCapture/LongCaptureSession.swift`、`LongCaptureEngine.swift` → `LongCaptureSession.cs`：仅开始时提示方向，拼接成功后清除提示，丢失对齐时不反复提示；所有非丢失帧都消费已使用的滚动量，包括“没有变化”的匹配帧。撤回 preview.2 自行添加的过程中提示。

## 平台适配与验证边界

- Apple 离线翻译、系统词典、Vision 与系统语言模型不能直接调用；使用已授权的 Windows OCR、系统语音和在线引擎。系统 OCR 没有二维码解码接口，本版该功能仍未实现，不能把禁用项算作完成。
- 标注与常用操作采用同一套原创矢量，圆头、线重、布局和工具含义按 Mac 参考调整；没有移植 SF Symbols。原生菜单、系统字体和背景材质的渲染仍有平台差异。
- Windows 显示排除按窗口全局设置，WGC 没有使用 Mac ScreenCaptureKit 那样的逐流窗口过滤。本实现还不能承诺同时录制与冻屏时，临时界面的排除时序逐帧完全相同。
- 本机验证 Windows 11 x64 与 WOW64 x86；未在 Windows 10、32 位操作系统、多显示器混合 DPI、各种声卡和显卡上逐一实机验证。在线协议使用本地假响应验证，未使用用户 Key 向真实服务发送验收请求。

这些边界是当前实现与验收范围，不等同于宣称所有平台差异都不可进一步改进。每次发现可实现的行为偏差，都应修正实现并增加对应的源行为检查。
